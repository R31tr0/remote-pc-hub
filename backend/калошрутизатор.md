# API Документация "Калошрутизатор"

Это руководство для фронтенд-разработчика по API для приложения Remote PC Hub.

**Базовый URL:** `http://localhost:8080`

**Аутентификация:** Большинство эндпоинтов требуют `Bearer` токен в заголовке `Authorization`.

```
Authorization: Bearer <ваш_jwt_токен>
```

---

## 1. Аутентификация (`/api/v1/auth`)

### Регистрация нового пользователя
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/auth/register`
- **Описание:** Создает нового пользователя.
- **Тело запроса:**
  ```json
  {
    "name": "имя_пользователя",
    "password": "пароль"
  }
  ```
- **Ответ (201 CREATED):**
  ```json
  {
    "id": 1,
    "name": "имя_пользователя"
  }
  ```
- **Ответ (400 Bad Request):** Если пользователь с таким именем уже существует.
  ```json
  {
    "username": "username is already registered."
  }
  ```

### Вход в систему
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/auth/login`
- **Описание:** Аутентифицирует пользователя и возвращает `accessToken`. В `HttpOnly` cookie `refreshToken` устанавливается для последующего обновления токена.
- **Тело запроса:**
  ```json
  {
    "name": "имя_пользователя",
    "password": "пароль"
  }
  ```
- **Ответ (200 OK):**
  ```json
  {
    "accessToken": "jwt_access_token"
  }
  ```
- **Ответ (401 Unauthorized):** Если неверные учетные данные.

### Обновление токена
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/auth/refresh`
- **Описание:** Использует `refreshToken` из cookie для получения нового `accessToken`.
- **Cookie:** Требуется `refreshToken`, который был установлен при логине.
- **Ответ (200 OK):**
  ```json
  {
    "accessToken": "новый_jwt_access_token"
  }
  ```

### Получение информации о текущем пользователе
- **Метод:** `GET`
- **Эндпоинт:** `/api/v1/auth/me`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Возвращает информацию о пользователе, которому принадлежит токен.
- **Ответ (200 OK):**
  ```json
  {
    "id": 1,
    "name": "имя_пользователя"
  }
  ```

## 2. Управление удаленными ПК (`/api/v1/pcs`)

### Добавление нового ПК
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/pcs`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Добавляет и сохраняет конфигурацию нового удаленного ПК.
- **Тело запроса:**
  ```json
  {
    "alias": "Мой рабочий комп",
    "host": "192.168.1.100",
    "port": 22,
    "username": "user",
    "password": "password123", // опционально
    "privateKey": "-----BEGIN RSA PRIVATE KEY-----..." // опционально
  }
  ```
- **Ответ (201 CREATED):**
  ```json
  {
    "id": 1,
    "alias": "Мой рабочий комп",
    "host": "192.168.1.100",
    "port": 22,
    "username": "user"
  }
  ```
- **Ответ (400 Bad Request):** Если не удалось подключиться с указанными данными.

### Получение списка ПК
- **Метод:** `GET`
- **Эндпоинт:** `/api/v1/pcs`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Возвращает список всех сохраненных ПК для текущего пользователя.
- **Ответ (200 OK):**
  ```json
  [
    {
      "id": 1,
      "alias": "Мой рабочий комп",
      "host": "192.168.1.100",
      "port": 22,
      "username": "user"
    }
  ]
  ```

### Удаление ПК
- **Метод:** `DELETE`
- **Эндпоинт:** `/api/v1/pcs/{id}`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Удаляет сохраненный ПК по его `id`.
- **Ответ (204 No Content):** Успешное удаление.

## 3. SSH-взаимодействие (`/api/v1/ssh`)

### Прямое SSH-подключение
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/ssh/connect/direct`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Устанавливает SSH-сессию, не используя сохраненную конфигурацию ПК.
- **Тело запроса:**
  ```json
  {
    "host": "192.168.1.100",
    "port": 22,
    "username": "user",
    "password": "password123"
  }
  ```
- **Ответ (200 OK):**
  ```json
  {
    "message": "Connection successful"
  }
  ```
- **Ответ (400 Bad Request):** Если подключение не удалось.

### Подключение через сохраненный ПК
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/ssh/connect/{pcId}`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Устанавливает SSH-сессию, используя конфигурацию сохраненного ПК по его `pcId`.
- **Тело запроса:** (пароль/ключ, если они не сохранены вместе с ПК)
  ```json
  {
    "password": "password123", // опционально
    "privateKey": "-----BEGIN RSA PRIVATE KEY-----..." // опционально
  }
  ```
- **Ответ (200 OK):**
  ```json
  {
    "message": "Connection successful"
  }
  ```

### Получение списка файлов
- **Метод:** `GET`
- **Эндпоинт:** `/api/v1/ssh/files`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Возвращает список файлов и папок в указанной директории.
- **Query-параметр:** `path` (например, `?path=/home/user`). По умолчанию `.` (домашняя директория).
- **Ответ (200 OK):**
  ```json
  [
    {
      "name": "document.txt",
      "size": 1024,
      "permissions": "-rw-r--r--",
      "isDirectory": false
    },
    {
      "name": "images",
      "size": 4096,
      "permissions": "drwxr-xr-x",
      "isDirectory": true
    }
  ]
  ```
- **Ответ (403 Forbidden):** Если нет прав на чтение директории.
- **Ответ (404 Not Found):** Если указанный путь не существует.

### Создание файла
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/ssh/files/create-file`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Создает пустой файл по указанному пути.
- **Тело запроса:**
  ```json
  {
    "path": "/home/user/new-file.txt"
  }
  ```
- **Ответ (201 Created):** Успешное создание.

### Создание директории
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/ssh/files/create-directory`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Создает новую директорию по указанному пути.
- **Тело запроса:**
  ```json
  {
    "path": "/home/user/new-folder"
  }
  ```
- **Ответ (201 Created):** Успешное создание.

### Удаление файла или директории
- **Метод:** `DELETE`
- **Эндпоинт:** `/api/v1/ssh/files`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Удаляет файл или директорию (рекурсивно).
- **Query-параметр:** `path` (например, `?path=/home/user/item-to-delete`).
- **Ответ (204 No Content):** Успешное удаление.

### Изменение прав доступа
- **Метод:** `PUT`
- **Эндпоинт:** `/api/v1/ssh/files/permissions`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Изменяет права доступа к файлу или директории.
- **Тело запроса:**
  ```json
  {
    "path": "/home/user/file.txt",
    "permissions": 755 // в восьмеричном формате
  }
  ```
- **Ответ (200 OK):** Успешное изменение.

### Скачивание файла
- **Метод:** `GET`
- **Эндпоинт:** `/api/v1/ssh/files/download`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Скачивает файл с удаленного сервера.
- **Query-параметр:** `path` (например, `?path=/home/user/file.txt`).
- **Ответ (200 OK):** Файл для скачивания.

### Загрузка файла
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/ssh/files/upload`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Загружает файл на удаленный сервер.
- **Тело запроса:** `multipart/form-data`
  - `file`: сам файл
  - `path`: полный путь для сохранения файла на сервере (включая имя файла)
- **Ответ (200 OK):** Успешная загрузка.

### Завершение SSH-сессии
- **Метод:** `POST`
- **Эндпоинт:** `/api/v1/ssh/disconnect`
- **Авторизация:** Требуется Bearer токен.
- **Описание:** Закрывает активную SSH-сессию для текущего пользователя.
- **Ответ (204 No Content):** Успешное завершение сессии.
